# LectureThread／課脈

串起投影片與講解，沿著老師的思路讀懂課程。

LectureThread 是一個持續開發中的課程閱讀工具：把投影片、整理後的講義、逐字稿與原始影音放在同一個閱讀介面，讓複習從閱讀開始，遇到疑問時再回到老師的原句與講解。

## 為什麼做這個專案

這個專案起於資工課程的學習需求。投影片通常只留下關鍵字與圖表，老師在課堂上補充的推導、例子和適用條件，則散落在影片裡。複習時，常常需要一邊看投影片，一邊反覆拖曳影片，才能把一個概念重新接起來。

我希望整理出能夠連貫閱讀的講義，保留老師如何提出問題、解釋原因、舉例與銜接下一個概念。同時，每一段整理都應該有回到來源的路徑，方便確認聽不清楚的術語，或重新理解某一步推理。

「課脈」想保留的，就是課程展開的脈絡。老師回到同一張投影片補充說明、加上註記，也應該留在閱讀順序裡。

## 目前的閱讀成果

![LectureThread 公開示範：左側投影片、右側講義，下方逐字稿標亮對應來源](docs/images/reader-demo.png)

*原創 stack／queue 示範畫面。左側看圖，右側讀解釋，需要核對時展開下方逐字稿。*

例如，讀到 queue 的「先進先出」時，可以同時對照圖中的加入與移除方向，再從講義段落找到對應原句。有實際課程影音時，還能直接聽這一段，或觀看原始影片，不必另外搜尋時間點。

目前閱讀器提供：

- **投影片與講義對照閱讀**：隨閱讀段落切換對應投影片，保留回頁與新增註記的順序。
- **從整理回到來源**：講義與逐字稿互相定位，可聽單句、聽段落或觀看影片；繼續播放時，跨章同步跟隨。
- **保留可核對的修訂**：原始逐字稿、校正版與人工修改分開保存，無法確認的詞與數字矛盾集中於待核對清單，不在逐字稿內插入提示小字。
- **依閱讀需要調整畫面**：調整投影片與文字的區域大小、放大投影片，或收起逐字稿；手機採上下對照。

## 試用公開示範

專案附有原創的 stack／queue 教材，包含三次投影片出現與六個閱讀段落，可以在自己的電腦上體驗對照閱讀、播放同步和人工校字。

**[開啟公開示範 →](docs/quickstart.md)**

目前入門步驟以 Windows x64／PowerShell 為準。示範不需要 GPU 或模型；首次建立 Python 環境需要網路連線。

示範共 36 秒，音訊是合成提示音，逐字稿是預先撰寫的教學腳本，沒有口語旁白或影片。它展示的是閱讀器的互動方式，不代表語音辨識或自動講義生成的品質。截圖與示範教材不包含實際課程資料。

### 原創端到端範例（含 ASR 與 OCR）

想實際走一次完整處理流程，可以用另一套原創微課程「循環佇列如何分辨空與滿」（約 3 分鐘，合成旁白，不是真人授課）：在本機產生 PDF、旁白與影片，執行語音辨識、原稿對齊與區域 OCR，人工核對畫面變化，校訂逐字稿、撰寫閱讀稿與講義，最後建置閱讀頁並對照標準答案評估。需要完整處理環境與 NVIDIA GPU。

## 目前階段與接下來的方向

LectureThread 目前是 Windows 本地研究原型，原始碼公開於 GitHub，已加入 Windows CI 設定，用於無模型的測試與示範建置；實際執行結果以 GitHub Actions 為準。實際課程資料保留在本機，公開原始碼不包含課程影音、模型或產生的閱讀頁。

完整課程處理目前有三條**彼此分開**的路線，尚未串成一個命令：

1. **舊整夜路線**：`lecture.cmd start`／`resume` 以本機模型依序產生逐字稿、投影片、AI 講義初稿、閱讀頁與待核對清單，支援進度與失敗續跑。它不會使用下面的原稿配對結果。
2. **原始投影片核對**：已有任務與原始投影片時，`lecture.cmd visual` 產生頁面配對、換頁補抓與局部差異的核對資料，完成狀態是「待人工核對」，不會自動改寫證據或發布講義。
3. **直接撰寫與發布**：沿用既有逐字稿與畫面證據，由 AI 助理直接撰寫分章講義，再用 `editorial_publish.py` 驗證並建置閱讀頁。

操作見 [睡前處理一堂課](docs/overnight.md)。目前沒有網址匯入的網頁介面；生成內容仍需抽查，講義與逐字稿依時間區間對照，切頁也有抽樣誤差。

接下來希望用更多課程評估講義品質與處理耗時，補上有口語旁白與影片的公開示範，並把原稿核對結果接進正式的證據與撰寫流程。
