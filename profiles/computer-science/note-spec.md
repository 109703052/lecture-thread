# 資工課程筆記規格

本規格取代上游醫學筆記格式；不是 Clinical Pearls、臨床診斷或治療排序。

主講義按概念與講師推進順序分章，不必把每次畫面變化都拆成獨立小講義。每個投影片出現區間仍須在來源對照層保留圖片、時間、對應章節與相關逐字稿，包含目錄、重複出現與結尾頁。去重只能節省辨識，不得刪除講解。來源對照的機械摘錄不能冒稱重新撰寫的教學內容。

資訊需求（主講義按章解釋，來源對照保留每次畫面，不強迫每張畫面各寫一份完整講義）：
1. 來源對照：投影片圖片、原文標題、影片起訖時間，以及對應的講義章節。
2. 本章重點：回答這一段講解要解決什麼問題。
3. 講師說明：依逐字稿整理因果、操作步驟、條件、例子與權衡，不自行刪除反例。
4. 教學脈絡（推論）：明確標示根據前後講解推論的銜接。
5. 補充與待核對：與講師原話分開；術語校對註明依據，不把不確定的數字改成確定事實。
6. 可回看的來源時間；逐字稿保持原始內容。

全課總覽：以「核心問題 → 分段推進 → 最後結論」整理，附可回看的代表時間。

資工特別規則：
- 保留英文專有名詞、符號、單位、假設及程式碼結構。
- 區分位元 bit 與位元組 byte；數字不一致時公開指出，不能默默更正。
- 區分 I/O 完成通知（interrupt / polling）、定址（port-mapped / memory-mapped）、資料搬移（CPU / DMA）。
- 不把示意圖中的一個硬體例子寫成所有架構的通則。
- 不把低 keyword overlap 當作講師略過；不根據圖像就聲稱知道講師意圖。
- 整理稿以繁體中文撰寫；原始轉錄的簡繁混合不直接覆寫。
- 外部補充若需要精確技術依據應另附來源；本輪優先用投影片及講稿能支持的解釋。

驗收：每個出現區間都有筆記與圖片；所有逐字稿片段有主要歸屬（跨頁片段可在鄰頁作上下文）；回看時間不超出影片；無醫學標籤；已知誤聽及內容矛盾有清單。


## 閱讀優先與逐字稿校正（使用者修訂）

- 總整理必須是可獨立閱讀的講義。沿講師順序直接講清楚問題、概念定義、機制／因果、例子與條件、取捨和結論，避免只寫「老師提到／老師介紹」的內容索引。
- 每個實質講解段落附來源時間，讀者不必先看影片即可理解，再按段落回看。短暫轉場只說明銜接，不捏造詳細內容。
- 原始 ASR、校訂逐字稿、修順閱讀稿與講義分層保存，依下節流程處理。原始 ASR 保存在 transcript.json；AI 校正版 transcript.corrected.json；校字依據 transcript.corrections.json；人工修訂 transcript.manual-edits.json。校訂逐字稿採用最新已核對的人工／線上修訂，不能只讀 AI 校正版。
- 校正保持片段順序、起訖時間及原意；可確認的專業術語直接改正，不只在筆記註腳提醒。無法確定的原詞與數值保留，疑點集中在待核對清單並附來源時間，不以常識偷偷改成標準答案。逐字稿與閱讀稿內不插入「待核對」、模型建議、模型依據或「已手動修訂」提示小字。
- 不宣稱已聽音確認實際僅依上下文校正的內容。數字矛盾、講師口述與投影片的矛盾仍需保留。
- 專業術語校訂優先對照該句時間範圍的投影片原圖文字，再結合前後逐字稿確認；OCR 僅作定位線索，不能把 OCR 誤字當作定論。特別留意英文術語的音近誤聽，例如 graphic collection／garbage collection、fresh memory／flash memory、reality issue／reliability issue。例子不是全域替換字典；只有該處投影片與語境支持，或使用者明確指定時才更正。修訂紀錄須記下時間、來源畫面及依據，並區分「依投影片核對」與「已聽音確認」。保留原始轉錄，透過獨立修訂層更新顯示；證據不足或圖文衝突時保留具體疑點，不自行補寫講師未說出的內容。

- AI 逐字稿校正與閱讀版一律使用繁體中文（臺灣字形），包含未發生誤聽修正的句子。簡體轉繁體屬字形正規化，需獨立記錄，不代表已聽音確認；原始 transcript.json 保持不變。保留英文術語、數值、符號及程式碼，不藉轉換改寫技術內容或強制替換地區詞彙。

## 新課程影片到發布的標準流程（2026-10-27 使用者確認）

這是後續課程的作業規範；不表示既有課程已產生閱讀稿，或網站已完成下述切換介面。更新規範本身不觸發舊課重寫或網站發布。

1. **建立來源與前課脈絡。** 保存影片、來源網址、課程日期與檔案 hash；先讀前一堂最新講義及未解問題。
2. **轉錄與抽取投影片。** 保存不可覆寫的原始 ASR 與時間碼。保留每次畫面出現、回訪與手寫變化；OCR 只作定位線索，不因去重或低關鍵詞重疊丟掉講解。
3. **先完成校訂逐字稿。** 對照同時間投影片原圖、前後講解與最新人工修訂，檢查全課重複術語，不只修單一出現位置。優先回聽會影響意思的數字、單位、否定與相近術語；沒有音訊證據時明確記錄限制。不可用常識或模型補寫取代原話。
4. **由 AI 修順獨立閱讀稿。** 以校訂逐字稿為依據，依下節界線刪冗詞、調整標點與語句；保留老師原話的校訂層，閱讀稿不回寫它。AI 作者預設由 Codex 執行；只有使用者明確要求時才用本機文字模型。
5. **整理講義與待核對清單。** 從校訂逐字稿、閱讀稿與投影片共同整理概念、機制、例子及推導。閱讀稿是衍生內容，不能取代原始證據。已解決的術語撤出待核對清單；只留下具體、有時間可回看的未解問題。
6. **內容及資料驗收。** 逐段比對閱讀稿和原話，完成下節忠實性檢查及後述教學品質檢查；另驗證來源 ID、時間、hash、畫面覆蓋、保存與播放／編輯功能。校對有漏段或輸出截斷時，補讀後才能宣稱完整檢查。
7. **提供修訂與發布。** 先提供可核對的成果；依使用者授權範圍更新本機或發布到 Sites。已明確授權「整理好後發布」時，驗收後直接完成，不重複索取確認。線上提交本身不自動改寫或發布講義。
8. **後續修訂連動。** 收集最新本機修訂與線上提交，處理版本衝突後，將受影響的閱讀稿、講義和待核對清單作為同一輪更新。記錄採納的版本及變更範圍，不能要求使用者再提醒一次「講義也要改」。

### AI 修順閱讀稿的界線

- **四層用途分開：** 原始轉錄保留模型最初輸出；校訂逐字稿修正誤聽與標點，保留老師措辭和順序；閱讀稿改善語句可讀性；講義重組教學脈絡並另標補充推導。
- 可刪無實質意義的「那、就是、這邊的話」、停頓及機械重複，可修標點、斷句及局部語序。只在指涉明確時補出主詞，不能把不明確的「它」猜成某個元件。
- 必須保留數字、單位、符號、英文專有名詞、條件、否定、因果、例子、反例與不確定語氣。「可能」「假設」「大約」不能修成確定結論。有教學意義的重述、強調和推理步驟不能當冗詞刪除。
- 老師自我更正時須保留更正關係；前後矛盾不能悄悄挑一個答案。內容不足時回到音訊或列入獨立清單，不用流暢文字掩蓋疑點。
- 不添加老師沒說的知識、不將閱讀稿擴寫成教材、不以摘要省掉實質講解；新增解釋只放講義，標明整理補充或推論。
- 每段保留對應校訂逐字稿的來源 ID 與時間範圍，合併相鄰句時仍能回到全部原句。不得改寫來源時間或為省字刪除來源映射。
- 記錄閱讀稿採用的校正版及人工修訂版本／hash。原話更新後，受影響閱讀稿必須重新比對；尚未更新時回退顯示最新校訂原話，不讓舊閱讀稿遮住新修訂。既有 transcript.reading.json 可作閱讀層容器，須遵守現有驗證格式；需要新增版本欄位或合句顯示能力時另行實作驗證，不能只靠規範宣稱已支援。
- 每段閱讀稿另附 `sentences`：把段落文字逐句切開（各句相接須等於整段原文），每句以 `source_ids` 標出它濃縮的連續校訂原句，依原話順序排列並涵蓋整段全部原句，相鄰兩句最多共用一句邊界原句。只含「那所以在這邊的話」之類銜接語的原句歸到它引出的下一句。可先用 `align_reading_sentences.py draft` 產生依文字重疊排列的草稿，逐段人工核對後再 `apply`；草稿不能直接當成已核對的對應。閱讀介面以此在滑鼠移到句子（觸控為點一下）時顯示對應原話。
- 閱讀介面目標為預設顯示閱讀稿、可切換「查看原話」，並保留來源時間與聽此段。此處「原話」指校訂逐字稿，不能宣稱未聽音的內容是完全精確的口述紀錄。校字編輯／提交以校訂逐字稿為對象，避免將潤飾後的句子誤存成老師原話；閱讀稿的建議須與原話勘誤分開辨認。

例子：校訂原話「那所以這邊的話，就是說我們這個 cell，這個 cell 裡面呢，它其實就是會存那個電荷。」可修成「這個 cell 裡面會儲存電荷。」若原句含「可能」「在這個例子裡」，閱讀稿也必須保留。

閱讀稿驗收須逐段確認：實質資訊未遺漏、語氣和條件未改變、無新增主張、術語與數字一致、自我更正和矛盾未被抹平、全部原句可定位回看。只有通順不代表校對正確；原始 ASR 與人工修訂檔案 hash 也須另行核對。

## 直白好理解的講義：寫作流程與驗收

目標讀者是資工背景的學生。讀者應能先讀懂講義，再用影片確認細節。白話是把關係講清楚，不是刪掉技術條件、推導或老師的反例。

### 先讀來源，再建立講解順序

1. 讀完整逐字稿，並核對相關投影片文字與必要原圖；不能只讀舊摘要或沿用模型舊稿。長課程可分段讀，但要保存已讀範圍與脈絡，確認沒有截斷或漏段。
2. 同系列先讀前課的最新講義與待核對事項，再定稿下一堂。區分老師已解釋、正在引入、留到後課但尚未解答的問題。
3. 先列本堂的核心問題和概念依賴。例如理解burst以前，先讓讀者知道row是什麼；介紹排程以前，先說seek和rotation各在等什麼。分章不必照OCR標題逐張切割。
4. 直接撰寫正文，為各段保留來源ID與時間；寫完先做下方教學品質檢查，再做發布驗證。不要把「來源全覆蓋」當作稿件已完成的唯一條件。

### 正文怎麼寫

- 先用一句話說「這是什麼、要解決什麼問題」，再解釋如何運作、例子及代價。依內容選擇需要的部分，不強迫每段填相同格式。
- 直接講概念，少用「老師提到」「課堂指出」「本稿不認定」等描述寫作過程的句子。不要靠反覆說「不是通則／不能推成」代替正面教學；必要條件仍要交代。
- 術語第一次出現時附簡短中文或白話解釋，之後保持名稱一致。不要為口語感杜撰比喻或把專業詞換成不準確的日常詞。
- 操作流程要交代起點、每步由誰做、資料／狀態如何改變、最後得到什麼；適合時用編號或箭頭。不要讓讀者只看到多個機制名稱，卻不知道如何配合。
- 硬體結構先說包含關係，再說操作。如模組→chip→bank→row／column→cell；結構層級、位址層級與傳輸單位分開說明，不能任意把各層數量相乘。
- 比較多種方法時，使用同一情境、同一組輸入或共同指標。說清楚各方法實際做了什麼，再比較收益與成本；表格或圖只在能幫助理解時使用。
- 算例列出假設、單位、公式、代入和結果，解釋結果代表什麼。bit／byte、rpm／每秒、KB／KiB等差異需公開標明。條件彼此矛盾時，分別列出可能結果，不能挑一組悄悄湊成答案。
- 保留老師的例子與反例。為理解新增的小例子要標成「整理補充／假設例子」，不能冒稱老師講過；新增外部技術主張依前述來源規則處理。
- 不確定處在影響理解的位置簡短標明，詳細原因與如何確認放checks。已能從原圖確認的內容應直接說清楚，不反覆寫成模糊的「可能OCR不清楚」。

### 交稿前再讀一次：教學品質檢查

逐章檢查，發現缺口就修改，不只回報「已依規格生成」：

- 不先看影片，讀者能說出本章的核心問題和答案嗎？正文是在教概念，還是在描述老師講了哪些名詞？
- 名詞之間的關係、結構層級、流程順序是否清楚？有沒有一句話跨過多個尚未解釋的概念？
- 老師的重要例子、推導、條件、取捨與反例是否被實質說明，而非只把來源ID分配給一段泛泛摘要？
- 算例可否照文字重算？圖、口述和算式衝突時，是否明確指出哪幾個條件不相容？
- 是否有長段審核口吻、重複警語或無用轉場？縮短它們時有沒有誤刪必要限制？
- 保留的疑點是否具體到能回看核對？來源全覆蓋、時間和hash驗證是否另外通過？

可由另一個agent做教學品質審閱；交接時須提供原始來源、前課脈絡、這份規格及已知疑點。使用者指定的子代理模型應照用，未指定時不自行假稱由某模型完成。任何模型都仍需此輪審閱，不能把模型名稱當作品質驗收。

語氣例子：

- 繞：「回到ready並不等於保證立刻取得CPU，這正是通知機制與排程決策需要分開理解的地方。」
- 直白：「Ready代表能夠參與排程，仍要等排程器選中才會開始執行。」
- 不足：「多個bank和chip可以共同提供頻寬。」
- 更完整：「先看圖中的層級，再說哪些資源如何參與操作；有了各層位寬、一次傳輸次數與單位，才能計算實際傳輸量。」具體內容仍須依該課來源填入。
